# Шаблон UNITYAGENT-UI.md

## Зачем нужен этот файл

Скилл `unity-ui` собирает и правит uGUI-префабы декларативными задачами `Task_*.ui.json` (без компиляции C# и domain reload). Перед вёрсткой он рекурсивно ищет в проекте файл `UNITYAGENT-UI.md` и читает соглашения вёрстки: референсное разрешение, палитру, шрифты, пути к арту и префабам. Без этого файла ИИ будет спрашивать соглашения у пользователя или угадывать.

**Ваша задача** — скопировать этот шаблон в свой проект как `UNITYAGENT-UI.md` (рядом с UI-кодом или в корне `Assets/UI/`) и заполнить реальными значениями проекта. Файл читается при каждой задаче вёрстки — пишите кратко и конкретно.

## Что описывать

- **Референсное разрешение** — под какой размер верстается UI (`shot`/`dump` по умолчанию 1920×1080).
- **Палитра** — именованные цвета в `#RRGGBB[AA]`, чтобы ИИ не подбирал их наугад.
- **Шрифты** — пути к `TMP_FontAsset`; какой шрифт для заголовков, какой для текста.
- **Арт** — где лежат спрайты окон, кнопок, иконок; какие `imageType` (Sliced/Simple) у каких спрайтов.
- **Префабы** — куда сохранять экраны/попапы; какие есть переиспользуемые части (nested-префабы) и их пути.
- **Компоненты-вью** — кастомные `MonoBehaviour`-вью (например `MapMissionView`) и какие у них поля (`set`) и ссылки (`ref`).

## Формат файла

```markdown
# UI-соглашения проекта

Одно-два предложения: под какое разрешение и в каком стиле верстается UI.

## Референс

Референсное разрешение: 1920x1080 (или ваше).

## Палитра

- Accent — `#FF005A`
- Background — `#0D0406`
- TextPrimary — `#FFFFFF`
- ...

## Шрифты

- Заголовки — `Assets/TextMesh Pro/Fonts/Strogo-Regular SDF.asset`, размер 42
- Основной текст — `Assets/.../Inter SDF.asset`, размер 28

## Арт

- Окна попапов — `Assets/Sprites/UI/PopUp_Window.png` (imageType: Sliced)
- Кнопки — `Assets/Sprites/UI/Button.png` (Sliced)
- Иконки — `Assets/Sprites/UI/Icons/*` (Simple)

## Префабы

- Экраны — `Assets/Resources/Prefabs/UI/Screens/`
- Попапы — `Assets/Resources/Prefabs/UI/Modals/`
- Переиспользуемые части — `Assets/Resources/Prefabs/UI/Parts/` (например `SkillNode.prefab`)

## Компоненты-вью

- `UI.MapMissionView` — `set`: `FloorFormat` (строка "Этаж {0}"); `ref`: `Icon` (Image), `Popup` (GameObject)
- ...
```

## Рекомендации

- **Именуйте цвета и шрифты.** ИИ подставит `#FF005A` увереннее, если знает, что это `Accent`, а не «розовый».
- **Указывайте `imageType`.** Для 9-slice окон и кнопок это `Sliced` — иначе спрайт растянется криво.
- **Давайте пути целиком** от `Assets/` — скилл грузит ассеты по точному пути (спрайты, шрифты, nested-префабы).
- **Опишите вью-компоненты.** Для собранного экрана важно заполнить `set`/`ref`, не оставляя пустых object-полей — перечислите поля каждого вью.
- **Пишите кратко.** Файл читается при каждой задаче вёрстки; это соглашения, а не полная документация UI-кита.

## Работа рядом с другими агентами

В одном редакторе может работать несколько агентов сразу. Мост выполняет задачи строго по одной и делит редактор между сессиями честно — но только если агент называет свою сессию.

- Один раз в начале работы сгенерируй id сессии: `AB_<дата-время>_<random>` — и передавай его каждой команде: `--session <id>`.
- По желанию добавляй `--note "<что делаешь>"` — держатель редактора увидит текст в поле `Contention` своих результатов.
- Поле `Contention` в результате задачи показывает, сколько чужих сессий ждёт редактор и как давно. Закончил серию задач — вызови `agentbridge release --session <id>`, не жди таймаута.
- Пока чужая сессия держит редактор, команда честно ждёт в очереди и печатает в stderr `queued <n>s, position <p>/<total>, holder <id>`. Это не зависание — не отменяй команду и не пересоздавай задачу.
- Сцены и открытый Prefab Stage запоминаются на сессию: когда редактор возвращается к твоей сессии, мост восстанавливает то, в чём ты работал.
