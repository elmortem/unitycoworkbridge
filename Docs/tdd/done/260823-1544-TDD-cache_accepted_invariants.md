# Кэш tests/compile — принятые инварианты двух-отпечатковой схемы

Дополнение к `260823-1500-TDD-test_compile_result_cache.md` после его выполнения с отклонением: вместо одного стартового снимка `GlobalArtifactDependencyVersion` кэш тестов охраняют два отпечатка — cache key (`TestFingerprint.Current()`, artifact-версия, штампуется на промоушене дампа) и source fingerprint (`TestFingerprint.Sources()` = `CompileFingerprint.Current()`, контент-хэш исходников на диске). Документ фиксирует два принятых следствия этой схемы, чтобы будущие ревизии кэша не приняли их за пропущенные баги. Изменений кода не требуется.

## References (not inlined)

- Схема и её обоснование: `AgentBridgeUnity/Packages/com.elmortem.agentbridge/Editor/TestFingerprint.cs` (комментарий класса).
- Промоушен дампа: `Editor/AgentTestRunner.cs` (штамп `dump.Fingerprint` на финализации), `Editor/TestCacheQuery.cs` (двойная сверка при выдаче).
- Известное ограничение про общий счётчик между режимами: задокументировано в `260823-1500-TDD-test_compile_result_cache.md`.

## Инвариант: неимпортированная правка ассета — кэш эквивалентен реальному рану

Правка ассета (не кода) на диске, ещё не импортированная Unity, не ловится ни одним из двух отпечатков: artifact-версия отражает только импортированное, а source fingerprint сканирует только `*.cs`/`*.asmdef`/`*.asmref`/`*.rsp` и файлы настроек. Это принятое поведение, а не дыра: реальный `tests`-ран тоже не делает refresh и бежит по уже импортированному состоянию, поэтому кэшированный ответ байт-в-байт совпадает с тем, что вернул бы настоящий запуск в тот же момент. Инвариант кэша — «кэш == реальный ран», а не «кэш == состояние диска». Для кода эквивалентность усилена: source fingerprint ловит неимпортированные правки исходников, потому что именно они — основной сценарий агента (поправил код → сразу просит тесты).

## Принятое окно: штамп cache key на промоушене

Cache key снимается после завершения рана и PlayMode-восстановления сцен, а не на старте. Импорт, проскочивший между концом рана и промоушеном, вписывается в ключ, хотя ран его не проверял. Окно принято как пренебрежимое: агентские таски сериализованы координатором, так что в это окно способен вклиниться только человек, руками трогающий редактор в момент финализации; правки кода при этом всё равно отсекаются source fingerprint-ом, который сверяется с состоянием на старте рана. Цена отказа — лишний реальный ран или кэш-хит по состоянию, отличающемуся на один человеческий импорт ассета; сужать окно (штамповать до финализации, догонять импорты) не нужно.
