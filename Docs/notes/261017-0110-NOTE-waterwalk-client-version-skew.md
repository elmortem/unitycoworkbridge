# WaterWalk: ложная пропажа задач при смешанных версиях CLI

Проверено 17.10.2026. Проект: `D:/Hobby/Repositories/waterwalk/WaterWalkUnity`.

## Подтверждённая причина

- Windows CLI: `1.26.0`; пакет открытого редактора: `0.37.0`, Unity `6000.4.0f1`.
- `Library/AgentBridge/cli/agentbridge` был Linux ELF `1.23.3+acf2d190b649a796f29abd5acf260ccc562874db`, от 02.10.2026.
- Старый `BridgeClient.WaitForTaskAsync` читает `Journal` и `Inbox`, не `Queue/Tasks`.
  Если журнал уже очищен, он возвращает `task_not_found`; при недоступности
  редактора во время ожидания — `bridge_unavailable`.
- В `Logs/AgentBridge-client-20261016.jsonl` найдено два таких `task_not_found`
  и один `bridge_unavailable`. Формат их телеметрии (`QueuedMs`, `RunningMs`,
  `Posts`, `Focuses`) совпадает со старым клиентом. Этих веток уже нет в CLI 1.26.0.
  Путь исполняемого файла старые события не содержат, поэтому конкретный
  процесс задним числом не установлен; обнаружена устаревшая проектная копия.
- Все три задачи сохранились в `Queue/Tasks`; их журналы в `Journal` уже отсутствуют.
  Потери этих задач диспетчером нет.

| TaskId | Результат повторного `wait` через 1.26.0 |
|---|---|
| `Task_20261016_201219_627_91433cb1` | `test_failure`, 10/11, evidence valid, exit 1 |
| `Task_20261016_211323_531_d769cc9b` | `test_failure`, 10/11, evidence valid, exit 1 |
| `Task_20261016_213915_645_9f8e400a` | `test_failure`, 10/11, evidence valid, exit 1 |

Все три прогона завершились на `MapRulesTests.PagesAreWithinLimits`: превышены
лимиты размера страниц карты проекта. Это сохранённый результат тестирования,
а не ошибка доставки задачи. Значение `valid` относится к входам того прогона,
не к текущим изменяющимся файлам WaterWalk.

## Исправление штатного обновления Windows (пакет 0.37.1)

В установщике был прямой `Copy-Item -Force` поверх установленного exe: Windows
блокирует такую запись, пока файл исполняется. Редактор запускал установку двух
копий отдельными командами и не останавливал оболочку при первой ошибке.
Это подтверждённые дефекты кода; журнал именно того старого обновления WaterWalk
не сохранился, поэтому его точный сценарий отказа не установлен.

- Windows-установщик принимает `-Project` и обновляет родную и проектную Linux-копию
  из одного заранее разрешённого релиза. Обе сборки проверяются и подготавливаются
  до замены; сбой второй замены откатывает первую.
- Занятый exe переименовывается, новая сборка занимает прежний путь. Работающий
  процесс продолжает выполнять запросы, новые команды используют новый файл.
  Старый файл, который ещё нельзя удалить, сохраняется с суффиксом `.previous-<id>`.
- Редактор вызывает один установщик, безопасно передаёт путь проекта через
  `EncodedCommand`, использует `UseBasicParsing` и возвращает ошибку скачивания
  или установки в Console вместо сообщения об успехе.
- `scripts/verify-installer.ps1`: PASS в Windows PowerShell 5.1. Проверены ZIP и
  tar.gz, единый релиз, архитектуры, отсутствие необязательных модулей PowerShell,
  ошибки хэша/скачивания/распаковки, откат при блокировке второй копии. Реальный
  работающий CLI ответил после замены своего exe, а новый exe успешно запустился.
  Скачивание подменялось локальными архивами; пользовательские процессы не останавливались.
- Unity compile: `Task_20261016_222115_237_ec93c18f`, success, `Evidence: valid`.
- Unity EditMode `CliUpdaterTests`: `Task_20261016_222133_391_3ed70222`, **4/4 PASS**,
  `Evidence: valid`. Настоящий дочерний PowerShell проверил успешную передачу пути
  с апострофом/Unicode и ненулевой код при ошибке скачивания либо установки.
- `build-plugin.ps1`: `version_check=PASS`, `invalid_entries=0`, `zip_validation=PASS`.
  Пакет поднят до 0.37.1; код и версия CLI не менялись. Изменения ещё не опубликованы.
