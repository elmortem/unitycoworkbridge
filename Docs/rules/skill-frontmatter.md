# Правило: frontmatter в `SKILL.md`

Инструкция появилась после реального инцидента: плагин собрался, ZIP прошёл проверки, а Claude Code
отказался грузить скилл с ошибкой

```
Skill 'skills/unity-bridge': field 'description' in SKILL.md must be at most 1024 characters
```

Сборка тогда ничего не проверяла кроме версий и целостности архива, поэтому битый скилл спокойно доехал
до пользователя. Ниже — жёсткие правила и способ проверки, чтобы это не повторилось.

## Лимиты

| Поле | Лимит | Считается |
|---|---|---|
| `name` | 64 символа | символы Unicode, не байты |
| `description` | **1024 символа** | символы Unicode, не байты |

Лимит по **символам**, а не по UTF-8-байтам — это проверено на практике: `skills/unity-ui/SKILL.md`
с описанием в 875 символов и 1046 байт грузится без ошибок, а `unity-bridge` с 1238 символами — нет.
Кириллица в описании не «дороже» латиницы, но и не бесплатна: держи запас хотя бы в 5–10 %.

## Требования к формату

1. Файл начинается со строки `---` и имеет закрывающую `---`.
2. Внутри frontmatter — только однострочные пары `ключ: значение`. Никаких блочных скаляров
   (`description: |`, `description: >`) и переносов: их длину нельзя надёжно проверить, и сборка их
   отклоняет.
3. `name` — lowercase kebab-case и **обязан совпадать с именем каталога** скилла
   (`skills/unity-bridge/SKILL.md` → `name: unity-bridge`).
4. `description` берётся в двойные кавычки; внутренние кавычки экранируются как `\"`.

## Как проверить

Проверка встроена в сборку плагина и работает fail-closed — превышение лимита валит сборку:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build-plugin.ps1 -ValidateOnly -SkipVersionCheck
```

Успешный вывод печатает фактические длины по каждому скиллу:

```text
skill_frontmatter=skills/unity-bridge/SKILL.md name=12/64 description=984/1024
skill_frontmatter=skills/unity-ui/SKILL.md name=8/64 description=875/1024
frontmatter_validation=PASS
```

Если правишь описание — **сначала посчитай длину, потом коммить**. Быстрый счёт без PowerShell:

```bash
python -c "
import re, io
t = io.open('unity-bridge-plugin/skills/unity-bridge/SKILL.md', encoding='utf-8').read()
print(len(re.search(r'^description:\s*\"(.*)\"\s*$', t, re.M).group(1)))
"
```

## Что делать, когда описание не влезает

`description` — это единственное, по чему агент решает, брать скилл или нет, поэтому резать надо
аккуратно, сохраняя триггеры:

- Убирай примеры-синонимы, а не классы триггеров. Из пяти фраз про плей мод достаточно двух —
  но сама тема «плей мод» из описания исчезать не должна.
- Убирай пояснения механики (её место — тело `SKILL.md`), оставляй условия применения.
- Сохраняй блок `Do NOT use for ...` и отсылку к соседнему скиллу: именно они разводят
  `unity-bridge` и `unity-ui`.
- Подробности, вылетевшие из описания, переноси в тело скилла, а не выбрасывай.
